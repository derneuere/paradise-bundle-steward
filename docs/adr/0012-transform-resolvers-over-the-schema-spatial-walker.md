# Spatial transforms go through per-resource resolvers, not the schema spatial walker

`src/lib/schema/spatial.ts` was a generic, tested walker that translated every field a **Schema** tagged `spatial: 'vec3'` / `spatial: 'vec2-xz'`, and it looked like the obvious seam for unifying the six per-resource transform op modules — one walker, tag the schemas, done. It never had a production caller: only three fields in the whole schema corpus carried the tag (all AI sections), and `aiSectionsOps/translateLinks.ts` — the one resource that *was* tagged — deliberately inlined the walk by hand. When we merged the six op modules into one **Transform** module we considered (a) reviving the walker as the generic engine and tagging the remaining five resources' schemas, (b) a per-resource **Resolver** that expands a **Ref** into leaf spatial slots and reads/writes each one, and (c) keeping both, with the walker as one resolver among many. We chose (b) and deleted the walker. Three things make the generic walk structurally unable to do this job, none of which is fixable by tagging more fields: it only translates, so the gizmo's three rotation rings have no counterpart; it takes a whole record and moves *every* tagged field beneath it, so it cannot express "move endpoint 1 of boundary line 3 of portal 2 only" — the sub-entity addressing every overlay's selection is built from; and it has no way to *not* move a field, which matters because several tagged-looking fields must never move (`PropCell.muX/muZ` are grid indices, `TrafficPvs.mGridMin/mCellSize` are a spatial hash, `SpawnLocation.direction` is an orientation, `TrafficLightTrigger.mDimensions` is an extent). A walker that found those by tag would corrupt them; `Resolver.expand` is hand-written per resource precisely so that what is *not* a slot is stated explicitly. The cost is real and worth naming: a new **Resource** does not get transforms for free — it needs a resolver, roughly 40–120 lines. We judged that a fair price for a format where a wrong write produces a corrupt game file rather than a visible error, and where "which of these floats is a position?" genuinely varies per resource.
