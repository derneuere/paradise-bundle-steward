# One Transform module — what ADR-0010 actually became

ADR-0010 decided that one gizmo unifies all spatial manipulation in the **WorldViewport**. It described the affordance but not the code behind it, and the code did not follow: six **Resources** each grew their own bulk op module *and* their own rigid (cardinality-1) op module — roughly 3,400 lines expressing one algorithm six times, with six byte-identical copies of `median`, six pivot walkers, six rotate-about-pivot closures and fourteen no-op guards. They had already drifted apart. `StreetDataOverlay`'s commit handler silently discarded the rotate delta, so street references could never be rotated at all. Worse, four families rotated `+X → +Z` with hand-rolled XZ math while three rotated `+X → −Z` through three.js `makeRotationFromEuler`, so a **Selection** mixing traffic junctions with static vehicles **counter-rotated** — and both directions were pinned by opposing assertions in the same test file, with doc comments on each claiming they agreed.

We consolidated onto one module, `src/lib/core/transform/`, with a per-**Resource** **Resolver** behind it (see ADR-0012 for why a resolver rather than the schema spatial walker). The structural decision that made it work is that the unit is not the **Ref** but the **slot** — a single leaf spatial datum with exactly one position. A **Ref** *expands* into slots, so a whole-section **Ref** yields every corner, portal anchor, boundary-line endpoint and no-go endpoint. That one move buys four things at once: a whole-container rotate turns its geometry instead of sliding its anchor; the **Pivot** is the median over resolved slots, which reproduces the old per-entity sampling weights for free; slot keys dedupe, so selecting a section *and* one of its own portals moves that portal once rather than twice; and cardinality 1 stops being a special case, which is what let the five rigid modules fold in.

Two things slot expansion could not express, and both changed the interface rather than being worked around. Orientation-bearing slots — traffic yaw packed in `Vector4.w`, trigger-box Euler, static-vehicle and prop `Matrix44` bases — need the gesture's *rotation*, not just a new position, so `SlotWrite` carries a `spin` alongside its absolute `point`; the shared math owns the orbit and every `T(P)·R·T(−P)` sandwich disappeared. And `write` is batched rather than per-slot, because folding one write per slot over a 500-section bulk rebuilds the sections array thousands of times a frame, and because the reference-identity contract that **Bundle** byte-for-byte writeback depends on can only be enforced coherently in one pass.

The rotation convention is now the true right-hand rule everywhere, and the gizmo's sign was flipped to compensate: the four XZ families are unchanged on screen, and the three matrix families are corrected. Range errors became silent skips — `expand`/`resolve` return `[]`/`null` — which is what every overlay already relied on. **Cascade** stayed outside the module as `expandAISectionsCascade(model, refs) → refs` per ADR-0009, which cost two accepted behaviour changes: cascade no longer drops `dy`, and cascaded slots orbit the shared **Pivot** rather than the source section's centroid.

What ADR-0010 promised and this did **not** deliver: the V4/V6 legacy overlay still has its own `TranslateGizmo`, `CornerHandles` and two private drag hooks, with cascade always on — contradicting ADR-0009 — and ADR-0010's claim that snap-to-edge was "reproduced via the cascade modifier or deferred" remains false, since `snapLegacySectionOffset` is still live. That port is deliberately outstanding: the V4/V6 fixture (`example/older builds/AI v6.DAT`) is absent from the local tree, so the three tests covering that format cannot run, and we judged an unverifiable migration of a deliberately frozen read-only prototype format to be the wrong thing to ship on trust.
